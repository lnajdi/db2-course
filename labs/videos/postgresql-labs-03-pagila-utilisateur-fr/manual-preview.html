PostgreSQL labs 03 - Pagila et utilisateur personnel

0-24s

Objectif

Base `pagila` prête, fichiers officiels importés dans le bon ordre, utilisateur personnel pour travailler sans rester connecté comme `postgres`.

24-72s

72-102s

Créer la base

CREATE DATABASE pagila;
\c pagila

`postgres` sert au setup et à l'administration.

102-142s

Importer le schéma

\i 'C:/Pagila_Project/pagila-schema.sql'

Le schéma crée les tables, les clés et les contraintes. Slashs `/` dans `psql`.

142-178s

Importer les données

\i 'C:/Pagila_Project/pagila-data.sql'
INSERT 0 1
COPY 1000
pagila=#

Les données remplissent les tables existantes. Attendre le retour de `pagila=#`.

178-220s

Utilisateur personnel

CREATE ROLE karim WITH LOGIN PASSWORD 'votre_mot_de_passe';
GRANT ALL PRIVILEGES ON DATABASE pagila TO karim;
GRANT ALL ON SCHEMA public TO karim;
GRANT ALL ON ALL TABLES IN SCHEMA public TO karim;
GRANT ALL ON ALL SEQUENCES IN SCHEMA public TO karim;

`karim` est un exemple; utiliser son prénom en minuscules. Mot de passe privé.

220-252s

Connexion CMD

psql -h localhost -p 5432 -U karim -d pagila

`-h` hôte, `-p` port, `-U` utilisateur, `-d` base. Si `psql` n'est pas reconnu: revoir PATH ou utiliser SQL Shell.

252-276s

Méta-commandes psql

\dt      -- liste les tables
\d film  -- décrit une table
\du      -- liste les rôles
\c pagila -- change de base
\q       -- quitte psql

Ce n'est pas du SQL et il n'y a pas de point-virgule.

276-296s

Vérifier et dépanner

\dt
SELECT COUNT(*) FROM film;

Si le schéma contient `OWNER TO student`, retélécharger le fichier officiel au lieu de l'éditer.
